# Security Policy

Do not publish a security defect in a public issue.

Use GitHub private vulnerability reporting for this repository. Include the
affected version, the effect, and the shortest safe reproduction procedure.
Do not include production credentials, user data, prompts, or model output.

The maintainers will confirm the report, assess the effect, and coordinate a
fix and disclosure date.

See `docs/threat-model.md` for the trust boundary this deployment assumes,
and for the known gaps under remediation.

If GitHub private vulnerability reporting is not available to you, email
security@confidential.ai instead.
